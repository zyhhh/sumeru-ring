# ADR-0002：统一内容目录，分离内容来源与访问行为

- 状态：已接受
- 日期：2026-08-18

## 背景

工作台同时包含随应用发布的内置工具和用户维护的网址。两者都需要被首页、列表、搜索、收藏和最近使用发现，但当前工具来自静态注册表，网址来自 IndexedDB，且全局搜索在 `AppShell` 中分别实现了两套逻辑。工具路由也需要单独维护，新增工具存在元数据与路由不同步的风险。

## 决策

建立统一的内容目录模块，向上层提供统一的内容查询与访问模型；目录内部保留两种内容来源：

- 内置工具来源：静态清单，包含页面路由和懒加载器。
- 用户网址来源：运行时网址仓库，包含外部 URL 和用户可编辑属性。

统一模型只抽象发现相关属性：稳定 ID、类型、标题、描述、分类、标签、关键词和图标。访问行为由类型决定：内置工具使用应用路由，用户网址使用新标签页和 `noopener,noreferrer`。

工具路由由内置工具清单派生，避免注册表与路由文件双维护。目录负责统一搜索、类型筛选和结果排序；页面不再分别拼接工具搜索与网址搜索。

## 影响

新增工具的主要修改集中到工具清单及其功能目录；首页、列表和全局搜索共享同一查询接口。用户网址仍由 IndexedDB 管理，不被强行转换成静态工具结构。未来可在目录之上加入收藏、最近使用和排序，而不改变两种来源的存储方式。

代价是需要引入一个应用层目录和来源适配接口，并补充目录到路由、搜索的契约测试。
