# SUMERU RING 架构设计

## 分层

1. 应用层：应用布局、路由、主题、全局搜索和侧栏。
2. 内容注册层：统一登记内容名称、类型、标签、图标、路由和描述。
3. 功能层：五个工具各自拥有页面、业务逻辑、类型和测试。
4. 基础设施层：本地存储、剪贴板、文件读取、Web Worker 与通知。

## 内容注册协议

首页、小工具列表和搜索不直接写死工具列表，而是读取 `contentRegistry`。网址属于用户可维护的运行时数据，因此通过 IndexedDB 仓库读取，不写入静态注册表。

每个注册项至少包含：

- 稳定 ID 与内容类型
- 中文名称、简短描述和路由
- 分类与标签
- Lucide 图标名称
- 搜索关键词

## 工具目录边界

每个工具位于 `src/features/<tool-name>/`：

- `views/`：负责页面交互和展示。
- `lib/`：纯业务函数，不依赖 Vue，便于测试。
- `components/`：只在该工具内复用的组件。
- `*.test.ts`：与核心逻辑相邻的单元测试。

通用页面结构放在 `src/components/tool/`，避免五个页面重复实现标题、页签、说明和操作区。

## 页面与路由职责

- `/`：全部内容概览，每种内容最多展示 5 项；总数超过 5 项时增加“查看更多”入口。
- `/tools`：完整小工具列表，支持标签筛选和每页 16 项分页。
- `/tools/*`：各工具详情页面。
- `/links`：完整网址导航，支持分类筛选和每页 16 项分页。
- `/links/manage`：网址新增、编辑、删除、排序、导入和导出。

路由通过 `meta.navigation` 声明所属侧栏入口。布局只依据该元信息计算激活状态，避免父路径或重复路径导致多个菜单同时高亮。

首页与完整列表页复用 `src/components/content/` 下的内容卡片，保证工具和网址的样式、安全属性与跳转行为一致。

## 数据与隐私

- JWT、密钥、JSON、URL、二维码内容和统计文本默认只存在内存中。
- 不把工具输入写入 localStorage。
- 主题、侧栏状态、收藏 ID 和最近使用 ID 可以保存在 localStorage。
- 二维码图片在本地读取与识别，不上传服务器。
- 网址导航数据保存在 IndexedDB，支持 JSON 导入导出；页面通过仓库接口访问数据，为未来后端同步保留替换边界。

## 性能策略

- JSON 目标规模为 1-10 MB，解析、格式化和转义在 Web Worker 中完成。
- 编辑器按路由懒加载，避免首页加载 Monaco。
- 工具页面采用动态 import，首屏只下载应用骨架与首页。
- 二维码与 JWT 依赖只在对应路由加载。

## 错误处理

- 用户输入错误采用页面内提示，说明错误位置和修复方向。
- 复制、下载等短操作使用消息提示。
- 未预期异常显示通用错误边界，同时在开发控制台保留原始错误。
- 不把“JWT 可解析”显示为“JWT 可信”；签名验证结果单独展示。
